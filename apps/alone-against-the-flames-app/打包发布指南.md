# 向火独行 — 打包发布指南

> 本文档记录从源代码到可分发的 Web 版及桌面应用（macOS / Windows）的完整打包流程。
> 最后更新: 2026-05-17

---

## 概览

打包分两个阶段：

1. **Web 版打包** — 将源码中的跨应用依赖内化，生成 `dist/` 目录下独立可运行的静态站点
2. **桌面应用打包** — 用 Electron 为 Web 版加壳，生成 macOS `.dmg` 和 Windows `.exe`

---

## 第一阶段：Web 版打包

### 1.1 目录结构认知

源码目录 `apps/alone-against-the-flames-app/` 并非完全自包含，存在一处跨应用依赖：

| 依赖项 | 引用位置 | 源头 |
|--------|----------|------|
| `dice-box/` 3D 骰子引擎库 | `js/adapters/dice-adapter.js` 第 1 行（ES import）+ 第 86 行（assetBaseUrl） | `apps/character-tracker/dice-box/` |

具体来说，`dice-adapter.js` 中有两处硬编码的跨应用相对路径：

```javascript
// 第 1 行
import DiceBox from "../../../character-tracker/dice-box/dice-box.es.min.js";

// 第 86 行
const assetBaseUrl = new URL("../../../character-tracker/dice-box/assets/", import.meta.url);
```

路径 `../../../character-tracker/dice-box/` 从 `js/adapters/` 向上三级回到 `apps/`，再进入 `character-tracker/`。这在开发仓库中可以工作，但打包后必须内化。

### 1.2 打包步骤

```bash
# 1. 创建 dist 目标目录
mkdir -p dist/alone-against-the-flames-app

# 2. 复制源码（排除开发工具和不必要的备用资源）
rsync -a --exclude='scripts' --exclude='figures-v4' \
  apps/alone-against-the-flames-app/ \
  dist/alone-against-the-flames-app/

# 3. 复制跨应用依赖：dice-box 库
rsync -a apps/character-tracker/dice-box/ \
  dist/alone-against-the-flames-app/dice-box/
```

dice-box 目录包含：
```
dice-box/
├── dice-box.es.min.js       ← ES Module 入口（193K）
├── Dice.min.js               ← 非 Module 版本（本 app 不使用）
├── world.onscreen.min.js     ← Offscreen Canvas Worker（382K，运行时由 DiceBox 加载）
└── assets/
    ├── ammo/
    │   └── ammo.wasm.wasm    ← WebAssembly 物理引擎
    └── themes/
        ├── coc/              ← 本 app 使用的主题（必须）
        ├── default/          ← 以下主题按需保留，全部保留最安全
        ├── diceOfRolling/
        ├── diceOfRolling-fate/
        ├── gemstone/
        ├── gemstoneMarble/
        ├── genesys/
        ├── rock/
        ├── rust/
        └── smooth/
```

### 1.3 修复跨应用路径

**关键：只修改 dist 副本，绝对不修改源码。**

编辑 `dist/alone-against-the-flames-app/js/adapters/dice-adapter.js`：

```javascript
// 修改前
import DiceBox from "../../../character-tracker/dice-box/dice-box.es.min.js";
const assetBaseUrl = new URL("../../../character-tracker/dice-box/assets/", import.meta.url);

// 修改后（dice-box 已复制到 app 根目录下，从 js/adapters/ 向上两级即可到达）
import DiceBox from "../../dice-box/dice-box.es.min.js";
const assetBaseUrl = new URL("../../dice-box/assets/", import.meta.url);
```

### 1.4 验证

```bash
# 确认 dist 中不再有跨应用路径引用（注释中的不算）
grep -rn "character-tracker" dist/alone-against-the-flames-app/js/ --include="*.js"
# 应只剩 skills-data.js 中的一条注释，不影响运行

# 确认不再有任何 ../../../ 路径遍历
grep -rn "\.\./\.\./\.\." dist/alone-against-the-flames-app/js/ --include="*.js"
# 应无输出
```

### 1.5 运行方式

Web 版需要通过 HTTP 服务器访问（原因：ES Module + `import json with { type: "json" }` + fetch 不支持 `file://` 协议）：

```bash
cd dist/alone-against-the-flames-app
python3 -m http.server 8080
# 浏览器打开 http://localhost:8080
```

### 1.6 可排除的内容

以下目录/文件对运行无影响，打包时可酌情排除：

| 排除项 | 原因 |
|--------|------|
| `scripts/` | 开发工具脚本（全文解析器等） |
| `figures-v4/` | 备用插图版本（272 张，与 `figures/` 互为备用） |
| `.DS_Store` | macOS 系统文件 |

## 第二阶段：桌面应用打包（Electron）

### 2.1 前置要求

- Node.js 26+（含 npm）
- macOS 构建环境（在 Mac 上构建 Mac + Windows 包）
- 网络连接（首次构建需下载 Electron 二进制文件 ~120MB）

### 2.2 构建工作目录

**关键：构建过程必须在仓库外进行，避免 node_modules 等中间文件污染源码库。**

```bash
# 在 /tmp 下创建独立的构建目录
BUILD_DIR="/tmp/aatf-electron-build"
mkdir -p "$BUILD_DIR"

# 将 dist 中的 Web 版复制为 Electron 的 app 目录
cp -R dist/alone-against-the-flames-app "$BUILD_DIR/app"
```

### 2.3 编写 Electron 入口文件

在 `$BUILD_DIR/main.js`：

```javascript
const { app, BrowserWindow } = require("electron");
const path = require("path");

function createWindow() {
  const win = new BrowserWindow({
    width: 1440,
    height: 900,
    minWidth: 1024,
    minHeight: 680,
    title: "向火独行",
    backgroundColor: "#0A0E14",
    webPreferences: {
      nodeIntegration: false,
      contextIsolation: true,
    },
    icon: path.join(__dirname, "app", "assets", "icon-64.png"),
  });

  win.loadFile(path.join(__dirname, "app", "index.html"));
  win.setMenu(null);
}

app.whenReady().then(createWindow);

app.on("window-all-closed", () => {
  app.quit();
});

app.on("activate", () => {
  if (BrowserWindow.getAllWindows().length === 0) createWindow();
});
```

要点：
- `nodeIntegration: false` + `contextIsolation: true` 确保安全隔离
- `win.setMenu(null)` 移除默认菜单栏（浏览器应用不需要）
- `win.loadFile()` 使用 `file://` 协议加载本地 HTML，Electron 内置的 Chromium 可正常运行 ES Module

### 2.4 编写 package.json

在 `$BUILD_DIR/package.json`：

```json
{
  "name": "alone-against-the-flames",
  "productName": "向火独行",
  "version": "1.0.0",
  "description": "克苏鲁的呼唤第七版 — 向火独行 单人模组电子陪跑",
  "main": "main.js",
  "scripts": {
    "start": "electron .",
    "build:mac": "electron-builder --mac",
    "build:win": "electron-builder --win --x64"
  },
  "build": {
    "appId": "com.coc7.alone-against-the-flames",
    "productName": "向火独行",
    "directories": {
      "output": "dist-packages"
    },
    "files": [
      "main.js",
      "app/**/*"
    ],
    "mac": {
      "target": [
        { "target": "dmg", "arch": ["arm64"] },
        { "target": "zip", "arch": ["arm64"] }
      ],
      "category": "public.app-category.role-playing-games",
      "icon": "icon.icns",
      "artifactName": "${productName}-${version}-mac-${arch}.${ext}"
    },
    "win": {
      "target": [
        { "target": "portable", "arch": ["x64"] }
      ],
      "icon": "icon.ico",
      "artifactName": "${productName}-${version}-win-${arch}.${ext}"
    }
  },
  "devDependencies": {
    "electron": "^35.0.0",
    "electron-builder": "^26.0.0"
  }
}
```

构建配置说明：

| 配置项 | 值 | 说明 |
|--------|-----|------|
| `files` | `["main.js", "app/**/*"]` | 只打包入口文件和 app 目录，排除 node_modules |
| `mac.target` | `dmg` + `zip` | dmg 方便用户安装，zip 方便解压即用 |
| `mac.arch` | `arm64` | Apple Silicon 原生；如需 Intel Mac 需加 `x64`；`universal` 合并两者但体积翻倍 |
| `win.target` | `portable` | 免安装单文件 exe，用户双击即用；也可选 `nsis`（安装程序） |
| `win.arch` | `x64` | Windows 主流架构 |

### 2.5 准备应用图标

Electron 需要特定格式的图标文件：

#### macOS (.icns)

```bash
# 源图标：app/assets/icon.jpg（1024x1024 JPEG）

# 1. 转为 PNG
sips -s format png app/assets/icon.jpg --out icon-1024.png

# 2. 生成 iconset（需要 10 个尺寸）
mkdir -p icon.iconset
sips -z 16 16 icon-1024.png --out icon.iconset/icon_16x16.png
sips -z 32 32 icon-1024.png --out icon.iconset/icon_16x16@2x.png
sips -z 32 32 icon-1024.png --out icon.iconset/icon_32x32.png
sips -z 64 64 icon-1024.png --out icon.iconset/icon_32x32@2x.png
sips -z 128 128 icon-1024.png --out icon.iconset/icon_128x128.png
sips -z 256 256 icon-1024.png --out icon.iconset/icon_128x128@2x.png
sips -z 256 256 icon-1024.png --out icon.iconset/icon_256x256.png
sips -z 512 512 icon-1024.png --out icon.iconset/icon_256x256@2x.png
sips -z 512 512 icon-1024.png --out icon.iconset/icon_512x512.png
sips -z 1024 1024 icon-1024.png --out icon.iconset/icon_512x512@2x.png

# 3. 打包为 icns
iconutil -c icns icon.iconset -o icon.icns
```

#### Windows (.ico)

```bash
# 使用 ImageMagick
magick icon-1024.png -resize 256x256 \
  -define icon:auto-resize=256,128,64,48,32,16 icon.ico
# 或旧版命令：convert icon-1024.png -resize 256x256 ...
```

#### 图标文件要求

| 平台 | 格式 | 源图最低要求 | 输出文件 |
|------|------|-------------|----------|
| macOS | `.icns` | 1024x1024 px | `icon.icns` |
| Windows | `.ico` | 256x256 px | `icon.ico` |

图标文件放在构建目录根目录（与 package.json 同级）。

### 2.6 安装依赖并构建

```bash
cd "$BUILD_DIR"

# 安装 Electron 和 electron-builder
npm install

# 先验证 Electron 能启动（可选）
npx electron . &
sleep 5 && kill %1

# 构建 Mac 版
npx electron-builder --mac

# 构建 Windows 版
npx electron-builder --win --x64
```

构建产物在 `$BUILD_DIR/dist-packages/` 下：

| 文件 | 说明 |
|------|------|
| `向火独行-1.0.0-mac-arm64.dmg` | macOS 安装镜像（Apple Silicon） |
| `向火独行-1.0.0-mac-arm64.zip` | macOS 免安装包（Apple Silicon） |
| `向火独行-1.0.0-win-x64.exe` | Windows 便携版（免安装，双击运行） |

### 2.7 收集产物并清理

```bash
# 复制最终产物到仓库 dist 目录
mkdir -p dist/alone-against-the-flames-app/desktop
cp "$BUILD_DIR/dist-packages/"*.dmg dist/alone-against-the-flames-app/desktop/
cp "$BUILD_DIR/dist-packages/"*.exe dist/alone-against-the-flames-app/desktop/
# 如有 zip 也可复制
cp "$BUILD_DIR/dist-packages/"*.zip dist/alone-against-the-flames-app/desktop/

# 清理构建目录（在 /tmp 下，重启后也会自动清除）
rm -rf "$BUILD_DIR"
```

## 常见问题

### Q: 为什么 Web 版不能直接双击 HTML 打开？

ES Module、`import ... with { type: "json" }`、`fetch()` 加载本地 JSON 等特性在 `file://` 协议下会被浏览器安全策略阻止。必须通过 HTTP 服务器访问。桌面版通过 Electron 内置 Chromium 解决此问题。

### Q: Mac 版首次打开提示"无法验证开发者"怎么办？

本应用未经 Apple 签名和公证（需要 Apple Developer 账号 + 年费 $99）。用户需右键点击应用 → 选择"打开" → 在弹出对话框中再次点击"打开"即可。

### Q: Windows 版被 SmartScreen 拦截怎么办？

同理，未签名应用会触发 SmartScreen 警告。用户点击"更多信息" → "仍要运行"即可。

### Q: 如何添加代码签名？

1. 注册 Apple Developer Program（macOS）和/或购买 Windows 代码签名证书
2. macOS：配置 electron-builder 的 `mac.identity` 字段，并在 `afterSign` 中配置 `notarize`
3. Windows：配置 `win.certificateFile` 和 `win.certificatePassword`

### Q: 如何构建 Intel Mac 版本？

在 `build.mac.target` 的 `arch` 数组中添加 `"x64"`，或构建时指定：

```bash
npx electron-builder --mac --x64
```

构建 `universal`（同时包含 arm64 + x64）：

```bash
npx electron-builder --mac --universal
```

universal 包体积约为单架构的 2 倍。

### Q: 构建时下载 Electron 二进制文件很慢怎么办？

可配置镜像源：

```bash
export ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
export ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
```

### Q: dice-box 的 WASM 文件在 Electron 中能正常工作吗？

可以。Electron 使用完整 Chromium 内核，WebAssembly 支持与 Chrome 浏览器一致，零兼容问题。

### Q: 如果更新了源码，需要重新走哪些步骤？

1. 重新执行第一阶段（复制源码 + dice-box + 修复路径）
2. 重新执行第二阶段（复制 Web 版到构建目录 + 重新构建桌面应用）
3. 两个阶段都必须完整重做，因为 dist 目录不应做增量更新
